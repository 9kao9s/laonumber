LUCKY · LIFF + SUPABASE
เขียนใหม่ทั้งหมด ไม่มี PHP ไม่มี MySQL
============================================================

โครงสร้าง
------------------------------------------------------------
  public/                      เว็บ static ทั้งหมด เอาขึ้น GitHub Pages ได้เลย
    index.html                 หน้าลูกค้า (LIFF)
    app.js  styles.css
    config.js                  <- กรอก 3 ค่าที่นี่
    admin/index.html           หลังบ้าน
    admin/admin.js
  supabase/
    schema.sql                 ตาราง + RLS + ฟังก์ชัน + cron
    functions/_shared/line.ts
    functions/play/            check / submit / receipt / slip
    functions/track-click/     เก็บสถิติการกดลิงก์

สถาปัตยกรรม
------------------------------------------------------------
  anon key  =  อ่านอย่างเดียว  ใช้โหลดกระดานเลขและค่าตั้งค่า
  การเขียนทุกอย่างของลูกค้า -> Edge Function ที่ verify LINE ID token ก่อน
  หลังบ้าน -> Supabase Auth (อีเมล/รหัสผ่าน) + RLS ตรวจว่าอยู่ใน admin_users

  แปลว่าต่อให้มีคนแกะ anon key ออกจากหน้าเว็บ (ซึ่งเห็นได้อยู่แล้ว)
  ก็จองเลขแทนคนอื่นไม่ได้ และแก้ข้อมูลอะไรไม่ได้เลย


ขั้นตอนที่ 1 · Supabase
------------------------------------------------------------
1. สร้างโปรเจกต์ใหม่ที่ supabase.com เลือก region Singapore
2. SQL Editor -> วาง supabase/schema.sql ทั้งไฟล์ -> Run
3. Storage -> New bucket ชื่อ  slips  -> ติ๊ก Public bucket
4. Project Settings > API จดไว้ 2 ค่า
     Project URL
     anon public key
   (service_role key ห้ามเอาไปใส่หน้าเว็บเด็ดขาด ใช้เฉพาะใน Edge Function
    ซึ่ง Supabase ใส่ให้อัตโนมัติอยู่แล้ว)


ขั้นตอนที่ 2 · LINE
------------------------------------------------------------
1. developers.line.biz -> Create channel -> LINE Login
2. แท็บ LIFF -> Add
     Size          Full
     Endpoint URL  https://ชื่อคุณ.github.io/lucky/
     Scope         ติ๊ก profile และ openid ทั้งคู่
     Share target picker  เปิด
3. จด LIFF ID (แท็บ LIFF) และ Channel ID (แท็บ Basic settings)


ขั้นตอนที่ 3 · Deploy Edge Functions
------------------------------------------------------------
  npm i -g supabase
  supabase login
  supabase link --project-ref <project-ref>

  supabase secrets set LINE_CHANNEL_ID=2001234567

  supabase functions deploy play --no-verify-jwt
  supabase functions deploy track-click --no-verify-jwt

--no-verify-jwt สำคัญ เพราะลูกค้าไม่ได้ล็อกอิน Supabase
เราตรวจตัวตนด้วย LINE ID token ข้างในฟังก์ชันเองแทน


ขั้นตอนที่ 4 · กรอกค่าและอัปหน้าเว็บ
------------------------------------------------------------
แก้ public/config.js

  SUPABASE_URL:      "https://xxxx.supabase.co"
  SUPABASE_ANON_KEY: "eyJhbG..."
  LIFF_ID:           "2001234567-AbCdEfGh"

แล้ว push โฟลเดอร์ public ขึ้น GitHub Pages
(หรือวางบนโฮสต์เดิมก็ได้ ไม่ต้องใช้ PHP แล้ว)


ขั้นตอนที่ 5 · สร้างแอดมิน
------------------------------------------------------------
1. Supabase > Authentication > Users > Add user
   ใส่อีเมล + รหัสผ่าน แล้วติ๊ก Auto Confirm User
2. คัดลอก User UID ที่ได้ แล้วรันใน SQL Editor

   insert into admin_users (user_id, email)
   values ('วาง-uuid-ที่นี่', 'admin@example.com');

3. เข้า https://.../admin/ แล้วล็อกอิน


ขั้นตอนที่ 6 · ทดสอบ
------------------------------------------------------------
A. เปิด https://liff.line.me/{LIFF_ID} จากมือถือที่มี LINE
   ครั้งแรกจะขึ้นหน้าขออนุญาต ให้กดยอมรับ
B. ชื่อในใบจองต้องถูกเติมจากชื่อ LINE อัตโนมัติ
C. เลือกเลขบน -> ระบบเด้งไปแท็บล่างให้เอง -> เลือกล่าง -> ยืนยัน
D. ปุ่มบนใบจองต้องเปิดหน้าต่างเลือกแชท LINE ไม่ใช่ดาวน์โหลดไฟล์
E. เข้าใหม่อีกรอบ -> ปุ่มต้องกลายเป็น "เปิดใบจองของฉัน"
F. ให้เพื่อนที่ต่อ WiFi วงเดียวกันเข้ามาจอง -> ต้องจองได้ตามปกติ
G. เปิดสองเครื่องพร้อมกัน เครื่องหนึ่งจองเลข -> อีกเครื่องต้องเห็นทันที
   โดยไม่ต้องรีเฟรช (Realtime)
H. หลังบ้าน -> แท็บลิงก์ ต้องเห็นคลิกที่เกิดขึ้นและอัตราแปลง


สิ่งที่ต่างจากของเดิม
------------------------------------------------------------
1. เลิกใช้ IP เป็นกุญแจสิทธิ์
   เปลี่ยนเป็น LINE userId ปัญหาคนต่อ WiFi ร้านเดียวกันแล้วโดนบล็อกหายไป
   และการสลับ 4G/WiFi เพื่อเล่นซ้ำก็ทำไม่ได้แล้ว

2. เลิก poll ทุก 10 วินาที
   ใช้ Supabase Realtime แทน กระดานอัปเดตทันทีที่มีคนจอง
   ยังมี poll สำรองทุก 45 วินาทีเผื่อ realtime หลุด

3. เงื่อนไขทั้งหมดถูกตัดสินในฐานข้อมูล
   ฟังก์ชัน claim_entry ทำทุกอย่างใน transaction เดียว
   ถ้าสองคนกดเลขเดียวกันพร้อมกัน unique index จะกันให้เอง
   ไม่มีทางที่เลขหนึ่งตัวจะมีสองเจ้าของ

4. เก็บสถิติลิงก์จริงจัง
   ทุกคลิกถูกบันทึกใน link_clicks พร้อมรหัสลิงก์
   ตอนจองสำเร็จระบบจะย้อนไปผูกคลิกล่าสุดของคนนั้นเข้ากับ entry
   หลังบ้านจึงคำนวณได้ว่าลิงก์ไหนพาคนมาจองจริงกี่คน (อัตราแปลง)

5. หลังบ้านทำได้เพิ่ม
   ประกาศผลและคำนวณเงินรางวัลอัตโนมัติ
   ระงับบัญชี LINE รายคน
   ดาวน์โหลด CSV
   แก้ข้อความหน้าเว็บ เวลาเปิด-ปิด และวันที่เปิด


ข้อควรระวัง
------------------------------------------------------------
1. โปรเจกต์ Supabase แบบฟรีจะถูกพักถ้าไม่มีการใช้งานประมาณ 1 สัปดาห์
   ถ้าเว็บนี้มีคนเข้าทุกวันก็ไม่โดน แต่ถ้าจะหยุดยาวควรเข้าไปกดปลุกไว้

2. ตาราง cron ในไฟล์ schema ตั้งเป็นเวลา UTC
   09:00 ไทย = 02:00 UTC ถ้าเปลี่ยนเวลาเปิดในหลังบ้าน
   ต้องแก้ตาราง cron ตามด้วย (SQL Editor: select cron.schedule(...))

3. ห้ามเอา service_role key ใส่ใน config.js หรือไฟล์ใด ๆ ใน public/
   ถ้าหลุดคือเปิดฐานข้อมูลทั้งก้อนให้คนอื่น

4. ก่อนเปิดใช้จริง ควรตรวจสองเรื่องนี้ก่อน
   - เงื่อนไขการใช้งาน LINE OA เรื่องบริการที่เกี่ยวข้องกับการพนัน
   - กิจกรรมชิงโชคแจกรางวัลในไทยต้องขออนุญาตตาม พ.ร.บ. การพนัน มาตรา 8
     ยื่นที่ที่ว่าการอำเภอหรือกรมการปกครอง
     แนะนำให้ปรึกษาผู้รู้ด้านกฎหมายก่อน
